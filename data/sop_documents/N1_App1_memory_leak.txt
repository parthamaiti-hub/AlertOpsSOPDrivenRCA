SOP: App1 Memory Leak Detection

1. SOP Definition
This SOP addresses memory leak alerts in App1 application services. It applies when heap memory usage shows continuous growth without corresponding garbage collection recovery, typically identified by steady memory increase over hours. Commonly affects long-running services with object reference leaks.

2. Triaging Steps
Step 1: Query Splunk for OutOfMemory errors, GC overhead warnings, and memory-related exceptions on the affected host.
Step 2: Query Prometheus for heap memory usage trend to confirm continuous growth pattern.
Step 3: Query Prometheus for garbage collection frequency and pause duration metrics.
Step 4: Perform a health check on the service to assess current availability and response time degradation.
Step 5: Determine if the leak is caused by cache growth, unclosed resources, listener accumulation, or third-party library issues.

3. Communication
Notify the development team and SRE via Teams with memory growth analysis, suspected leak source, and recommended actions (restart schedule, heap dump analysis).
